# v0.3 轮：分步处理 + 压缩预览 + 输出目录命名（开发者口述需求）实施计划

**Spec:** `2026-10-06-fileforge-design.md`（设计全记录）；需求变更：`design.md` v0.3（待审核）；开发依据：同目录 `designs-specs.md`

> 三条需求：① 上传后先预览、点「开始转换」才压缩（两段式）；② 待确认时展示每文件在当前质量下的精确输出大小（真实编码一次），滑块调整即刷新；③ outputs/ 按创建时间命名目录（YYMMDD-HHMM，冲突加 -2/-3），zip 同名；运行产物入 .gitignore、docs/ 全部入库。

## 任务序列（TDD）

1. **store**：新增 `TaskReady` 状态常量与 `DirName` 字段（Task/TaskView/TaskSummary 不加 DirName——历史表不展示）。
2. **service（TDD）**：
   - `CreateTask(fhs)`：不再接并发/质量；状态 = ready；计算 `DirName`（`061002-1504` 格式，已存在则追加 `-2/-3`）；
   - `Start(id, concurrency, quality)`：仅 ready 任务可开始（否则报错），设参后执行 Run；
   - `Estimate(id, quality)`：待确认任务按质量真实编码每个文件（有界 worker 池，不写盘），返回每文件精确输出大小与总量；损坏文件带错误标记。
3. **handler（TDD）**：
   - `POST /api/tasks`：只收文件 → 返回 ready 任务；
   - `POST /api/tasks/{id}/start`：body `{concurrency, quality}` → 开始处理；未知 404；非 ready 409；
   - `GET /api/tasks/{id}/estimate?quality=N`：返回预览数据；非 ready 409；
   - zip 下载文件名改 `fileforge-<DirName>.zip`。
4. **前端**：上传后列表加「压缩后（预估）」列与总览行；滑块防抖 400ms 刷新预估（进行中显示转圈文案）；新增「开始转换」按钮（待确认时显示）；开始后逻辑复用 SSE 进度流。
5. **验证**：`go vet`、`go test -race`、`go build`；浏览器全流程：上传 → 预览（改滑块看数字变）→ 开始转换 → 进度 → 下载 zip（文件名含时间目录名）。

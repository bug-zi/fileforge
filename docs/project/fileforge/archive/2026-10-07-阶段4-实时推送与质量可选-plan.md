# 阶段 4：SSE 实时推送 + 压缩程度可选（design v0.2）实施计划

- 已归档：261007 随阶段 4 落地（vet / test -race / build 全绿；浏览器实测 SSE 长连接推帧、质量 50 vs 80 产出 358.6KB vs 538KB）

**Spec:** `2026-10-06-fileforge-design.md`（设计全记录）；需求变更：`design.md` v0.2（压缩程度可选，待审核）；开发依据：同目录 `designs-specs.md`

> 目标：进度条无刷新实时跳动（SSE，轮询为降级备份）；用户可自选压缩质量（50~95，默认 80）。

## 任务序列（TDD）

1. **store**：`Task/TaskView/TaskSummary` 增加 `Quality` 字段。
2. **processor（TDD）**：`Process(data, quality)`——签名加质量参数；新增测试：同输入 q50 输出 < q90 输出；存量测试补质量参数。
3. **service（TDD）**：`CreateTask` 增加 quality 参数入表；`processOne` 用 `task.Quality`；新增**进度广播器**：`Subscribe(id)` / `notify`（每文件终结推送 `{done,total,last}`，任务完成推送 `final:true` 后关闭订阅）。
4. **handler（TDD）**：`POST /api/tasks` 增加 `quality` 参数（钳位 50~95，缺省 80）；task/history JSON 增加 quality；新增 `GET /api/tasks/:id/events`（SSE：text/event-stream，任务已 done 时立即发 final）。
5. **前端**：压缩质量滑块（低=更小 / 高=更清晰提示）；进度改 `EventSource` 优先，error/最终态回退轮询 + 收尾拉一次全量文件列表。
6. **验证**：`go vet`、`go test -race`、`go build`；浏览器实测 SSE 实时进度与质量滑块生效（不同质量产出体积差异）。

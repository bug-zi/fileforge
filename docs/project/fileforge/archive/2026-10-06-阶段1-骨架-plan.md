> 目标（验收标准）：浏览器拖文件，服务端收得到、列表列得出。
> 本阶段不含压缩/去重/重命名（阶段 2）与 worker 池/SSE/zip（阶段 3+）。

## 任务序列

1. **模块初始化**：`go mod init fileforge`；`go get github.com/gin-gonic/gin` + `go get golang.org/x/image/draw`。
2. **store（TDD）**：`internal/store/store.go`——`FileItem`/`Task`/`TaskSummary` 类型 + `CreateTask`/`GetTask`/`ListHistory`（mutex + map）。先写 `store_test.go`：建任务可查、未知 ID 查不到、并发读写无竞态。
3. **handler 上传（TDD）**：`internal/handler/task.go`——`POST /api/tasks`（multipart 流式落盘 `uploads/<id>/`、concurrency 钳位 1~32）+ `GET /api/tasks/{id}` + `GET /api/history`。先写 `httptest` 用例：上传 2 文件→200 返回 id 与文件列表→GET 可查；未知 ID→404。
4. **service 骨架**：`internal/service/service.go`——`CreateTask` 复用（落盘 + 建 Task + 入 store）；`Run` 本阶段为空实现（阶段 3 填 worker 池），仅保留异步启动签名。
5. **main.go**：装配 store/handler，`gin` 路由 + `go:embed web` 静态页 + `:8080` 监听 + 启动日志（`FileForge 已启动，请打开 http://localhost:8080`）。
6. **前端骨架**：`web/index.html` + `web/app.js`——拖拽区（含隐藏 file input 兜底）、并发滑块（1~32）、上传 fetch、文件列表渲染（文件名 + 大小）。
7. **验证**：`go vet ./...`、`go test -race ./...`、`go build -o fileforge.exe .`；运行 exe，浏览器实测拖拽上传 → 列表显示。

## 任务序列（TDD：每项先写测试看失败，再实现）

1. **processor 补 MD5Hex（TDD）**：worker 先算 MD5 判重、命中即跳过压缩（避免重复文件白压），需要独立于 `Process` 的 MD5 入口；测试断言与 `Result.MD5` 一致。
2. **service worker 池（TDD）**：
   - `Run(task)`：带缓冲 channel 分发 `*FileItem` → N 个 worker（N=并发数）→ `sync.WaitGroup` 收尾 → `task.Finish(elapsed)`；
   - worker 单文件：读盘 → `MD5Hex` 判重（`Run` 内局部 `map+mutex`，先到先得）→ 未重复则 `Process` → 写 `outputs/<taskID>/photo_NNN.jpg`（序号 `atomic.Int64`，完成序）→ 全程 `task.Lock()` 更新 FileItem；`defer recover()` 单点隔离；每文件终结时 `task.AddDone()`；
   - `store.GetRef(id)`：service 持可变实体的专用入口（读方仍走 `GetTask` 快照）；
   - `Service.New` 增加 outputs 根目录参数（`uploads/`、`outputs/` 分离）；
   - 集成测试：4 文件（2 独立图 + 1 重复 + 1 损坏）同步跑完 → done=2 / duplicate=1 / failed=1、Elapsed>0、outputs 恰 2 个可解码 jpg。
3. **handler zip 下载（TDD）**：`GET /api/tasks/{id}/download`——未知 ID 404；`archive/zip` 流式打包 outputs（只含 done 文件，文件名扁平 photo_NNN.jpg）。已有上传测试改用真实 JPEG 字节并把状态断言放宽为 pending/processing/done 任一（上传即异步开跑，断言不再强依赖瞬间状态）。
4. **前端进度 + 下载**：总进度条（done/total）+ 三种结局统计 + 完成后「下载结果 zip」按钮；1s 轮询，任务 done 停表。
5. **验证**：`go vet`、`go test -race ./...`、`go build`；浏览器整批闭环实测（含重复与损坏文件），解压核验 zip。
